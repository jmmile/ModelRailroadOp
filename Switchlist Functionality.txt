The important thing is to build them in stages rather than trying to create the entire switch-list system at once.

### Recommended next phase: Switch Lists

I'd build it in this order:

1. **Switch List data/model**

   * Session
   * Car
   * Current location
   * Pickup location
   * Setout location
   * Move type/status

2. **Switch List generation**

   * Look at active waybills.
   * Find cars that need to move.
   * Determine pickup location from the car's current Industry → Track → Spot.
   * Determine setout location from the waybill destination.

3. **Switch List screen**

   Something like:

   | Move | Car        | From           | Pick Up          | To             | Set Out          |
   | ---- | ---------- | -------------- | ---------------- | -------------- | ---------------- |
   | 1    | UP 12345   | Cascade Lumber | Track 2 / Spot 3 | Pacific Paper  | Track 1 / Spot 2 |
   | 2    | ATSF 45678 | Acme Feed      | Track 1 / Spot 4 | Cascade Lumber | Track 3 / Spot 1 |

4. **Operator execution**

   * Select a move.
   * Execute it.
   * The car's Industry → Track → Spot changes.
   * Car History records the movement.

5. **Completed moves**

   * Mark moves completed.
   * Update the waybill.
   * Remove completed moves from the active switch list.

### Where I'd put it in the application

You already have:

**Waybills**
**Operations Sessions**

I'd add:

**Switch List**

as another main tab.

Eventually the workflow becomes:

**Car Roster → Waybill → Operations Session → Switch List → Execute Moves → Car History**
