# 1. Project Purpose

ModelRailroadOps is a desktop application for managing a model railroad operating system.

The long-term goal is to manage:

* Railroad cars
* Industries
* Industry tracks
* Individual spots
* Car locations
* Car loading/empty status
* Spot restrictions
* Car assignments
* Switching operations
* Eventually, switch lists / operating sessions

The desired location hierarchy for cars is:

**Industry → Track → Spot**

For example:

`Cascade Feed → Grain Track → Spot 3 → BN 123456`

The application is being developed incrementally so that each major feature is fully functional before moving to the next.

---

# 2. Current Development Philosophy

The project is being developed in small, testable stages.

A major lesson from recent development is that changing several files at once makes debugging unnecessarily difficult.

Therefore:

* Change one logical component at a time.
* Run the application after each significant change.
* Test the exact behavior that was changed.
* Use diagnostic output when a UI event is not behaving as expected.
* Once the feature works, remove temporary debugging output.
* Do not assume a UI problem is a database problem without testing the layers separately.

The preferred coding workflow is:

1. Identify the exact file involved.
2. Replace the complete file.
3. Run the application.
4. Test one specific behavior.
5. Report the actual result.
6. Only then move to the next file/change.

---

The project uses SQLite with SQLAlchemy.

The database contains at least these major entities:

* `cars`

Relationships are being built so that the hierarchy is:

```text
Industry
   └── IndustryTrack

                 └── Car
```

# 7. Industry Model

The Industry model represents a railroad-served industry.

Important fields:

* `id`
* `name`
* `railroad`
* `location`
* `notes`

An industry has a relationship to its tracks.

The industry name has a unique constraint:

```text
uq_industry_name
```

This was added because duplicate industries were previously being created.

Duplicate protection also exists in `IndustryService.add()`.

---

# 8. Industry Track Model

The `IndustryTrack` model represents a track belonging to an industry.

Important fields:

* `id`
* `industry_id`
* `name`

The model contains a unique constraint preventing two tracks with the same name under the same industry:

```text
uq_industry_track_name
```

The track has relationships to:

* Parent industry
* Individual spots
* Cars assigned to the track

Important relationship:

```text
spots = relationship(
    "Spot",
    back_populates="track",
    cascade="all, delete-orphan",
    order_by="Spot.spot_number",
)
```

This means deleting a track can cascade-delete its spots, provided the application/database rules allow the track to be deleted.

Cars have a relationship to the track as well.

---

# 9. Spot Model / Functionality

Spots are individual car positions on an industry track.

A spot can contain a car or be empty.

Spot information currently includes:

* Spot number
* Name
* Description
* Maximum length
* Allowed car type
* Allowed owner
* Hazardous allowed
* Load only
* Empty only
* Notes

The Industry Tracks tab displays spots in a dedicated table.

The current spot table columns are:

1. Spot
2. Name
3. Description
4. Max Length
5. Allowed Car Type
6. Allowed Owner
7. Load / Empty
8. Status

The status can display:

```text
Empty
```

or:

```text
Occupied - BN 123456
```

when a car is assigned.

# 10. Industry Tracks Table

The Industry Tracks table currently displays:

1. Industry
2. Track Name
3. Spots
4. Occupied
5. Available

The table model is:

`IndustryTrackTableModel`

It deliberately displays **every industry**, including industries that have no tracks.

For an industry without tracks, it displays:

```text
Track Name = No Tracks
Spots = 0
Occupied = 0
Available = 0
```

The underlying track value for such a row is:

```text
None
```

This is intentional.

It allows the user to select an industry that has no tracks and immediately use **Add Track** to create its first track.

---

# 11. Track Sorting

The Industry Tracks table was recently changed so that tracks are sorted alphabetically within each industry.

The overall industry order is alphabetical.

For each industry:

```text
sorted_tracks = sorted(
    industry.tracks,
    key=lambda item: (
        item.name or ""
    ).lower(),
)
```

The result is that a newly added track appears in its proper alphabetical position rather than simply being appended to the bottom of the table.

This functionality is currently working.

# 12. Industry Capacity Calculations

The Industry service calculates capacity while the SQLAlchemy session is still active.

For each industry:

* `capacity_total`
* `capacity_occupied`
* `capacity_available`
* `capacity_percent`

are calculated from the industry's tracks and spots.

The calculations are based on actual spots.

For example:

```text
Total spots = 5
Occupied = 2
Available = 3
Capacity = 40%
```

An industry with zero spots has:

```text
Total = 0
Occupied = 0
Available = 0
Percent = 0
```

# 19. Spot Delete Rules

The current intended rules are:

### Empty spot

Can be deleted.

### Occupied spot

Cannot be deleted.

The Delete Spot button should be disabled when the selected spot contains a car.

The application also performs a final occupancy check immediately before deletion.

This prevents a race/stale-state situation where the UI says the spot is empty but a car was assigned after the initial check.

# 23. IndustryService

Loads:

* Industries
* Tracks
* Spots
* Cars associated with spots

using SQLAlchemy eager loading.

### `add()`

Adds an industry.

It checks for an existing industry with the same name.

IndustryService.add(): VERIFICATION SUCCESS.

This debugging output has been removed/reduced during recent cleanup.

The final desired behavior is a clean console when running the application normally.

### `update()`

Updates an industry.

It checks for another industry using the requested name.

### `delete()`

Deletes an industry.
